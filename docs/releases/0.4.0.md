# StoryMap 0.4.0

Prepared 2026-09-30. Adds three features: a `timeline` layout, `initialSlide`, and
`panelOpacity`. The private workspace root, site and example package versions are
independent.

This is a **minor** release, not a patch: `panelOpacity` is a new required field on
`StoryMapConfig`, so hand-written TypeScript configs must add it. See
[Upgrade notes](#upgrade-notes).

## Highlights

- **Timeline layout.** `layout.mode: 'timeline'` renders every slide as a dated,
  thumbnailed row in a scrollable column beside the full-bleed map: a date chip, an
  image-only cover thumbnail, a title, a two-line clamped description, and a note link.
  The list is the navigation, so there is no previous/next control; clicking a row
  selects that slide and the active row scrolls into view with `block: 'nearest'`.
  Timeline reuses `layout.full.side` and `layout.full.contentRatio` and adds no new
  configuration key.
- **Slide dates.** A new `StorySlide.date` (epoch milliseconds) carries each entry's
  date. Both the Obsidian and Remark adapters fill it from the existing `dateField`
  frontmatter value, and an explicit slide may author its own. Dates format as
  `Apr 12, 2024` with a fixed `en-US`/UTC formatter, so server markup and browser
  hydration agree.
- **`initialSlide`.** Choose which slide a story opens on: `first`, `last`, or a
  zero-based index. Available in Obsidian plugin settings as a default.
- **`panelOpacity`.** A `0.0`–`1.0` translucency for the card/article background, so
  the map shows through behind the text. The map itself stays opaque. Also an Obsidian
  plugin setting.

## Upgrade notes

Existing YAML documents need no edits; the parser supplies defaults for the new fields.
The source schema identifier remains `storymap/v1`, and no new required source key was
added, so already-published Docusaurus pages keep rendering against the new renderer.

**Direct TypeScript construction of `StoryMapConfig` now requires `panelOpacity`.**
A hand-written object literal that omits it fails to compile with `TS2741`:

```ts
import type { StoryMapConfig } from '@story-map/story-map-core';

const story: StoryMapConfig = {
  schema: 'storymap/v1',
  height: '400px',
  // NEW in 0.4.0 — required. Use 0.85 for the previous solid panel.
  panelOpacity: 0.85,
  map: { theme: 'light', zoom: 3, tileUrl: '…', attribution: '…', showPath: false },
  layout: { mode: 'card', card: { align: 'left' }, full: { side: 'left', contentRatio: 0.5 } },
  slides: [/* … */],
};
```

`initialSlide` is optional and is only set on the config when the resolved index is
greater than zero.

The supported alternative is to build the config through the parser, which fills both
fields:

```ts
import { parseStoryMapSourceYaml, toStoryMapConfig } from '@story-map/story-map-core';

const source = parseStoryMapSourceYaml(yaml);
const story = toStoryMapConfig(source, source.slides ?? []);
```

### New configuration keys

| Key | Default | Defaultable in Obsidian |
| --- | --- | --- |
| `initialSlide` | `first` | yes |
| `panelOpacity` | `0.85` | yes |

`layout` remains document-only and is **not** a plugin setting, including its new
`timeline` mode. A legacy root-level `opacity`, or `map.opacity`, is normalized into
`panelOpacity` and then removed, so an explicit `panelOpacity` always wins.

### Timeline note display

Only the `full` layout forces `noteDisplay: full`. A timeline honors the configured
value, and both adapters keep the frontmatter title, cover and date beside the note
body when the display is `full`, so a timeline row is never empty. `card` and `full`
behavior is unchanged.

## Known limitations

- The row-wide select button covers the whole timeline row, so text inside a row is not
  selectable and a cover thumbnail has no right-click menu. This affects timeline rows
  only.
- Blue Topaz can override bold text with a light `!important` color, reducing contrast
  in Atlas. This release does not fix that host CSS conflict. See the
  [Atlas comparison](../acceptance/2026-09-28-atlas-comparison.md).
- Map tiles and remote example media require access to their external providers.
- Production site/example builds still report large JavaScript chunk warnings.
- `VaultIndex.resolveStory` takes an optional `dateField` that defaults to the built-in
  `date-created`, because `StoryMapConfig` does not carry one. Hosts that re-resolve an
  already-normalized config with a custom `dateField` must pass it explicitly.
